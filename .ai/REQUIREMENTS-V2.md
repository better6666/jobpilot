# V2 需求台账 —— Get Jobs 商业化三档会员

> 建立于 2026-09-22。来源：用户商业方案原话（三档定价 + entitlement 架构 + 禁止假功能）。
> 本篇只记 V2 商业化改造，P1/P2 的投递能力台账见 REQUIREMENTS.md / REQUIREMENTS-P2.md。

## 1. 需求来源（用户原话要点）

- 产品定位是「AI 求职 Agent」，不是自动点击工具
- 只留三档：体验版 / 标准版 / 进阶版，不许 Platinum/Pro Max 之类
- 价格：体验 ¥2.9/3天；标准 30/60/90 天 = ¥19.9/29.9/39.9；进阶 30/60/90 天 = ¥32.9/39.9/59.9
- 进阶 60 天 ¥39.9 是重点推荐，UI 要标「🔥最受欢迎 / 推荐 / 性价比最高」，但**不许用虚假倒计时、虚假原价、虚假库存**
- 必须建统一 entitlement / feature flag 系统，不许在前端到处 `if pro if vip`
- **前后端都要校验权限，不能只隐藏前端按钮**
- 额度要后台可配置，「不要把价格和额度完全写死在代码」
- 到期只关付费功能，不删简历/规则/投递记录/数据
- 遇到验证码 / 登录异常 / 平台异常必须停止并提示人工接管，不许做破解和绕过
- 禁止：只画 UI、假按钮、Mock 成功、写 TODO 然后声称完成

## 2. 审计结论（真实代码，非猜测）

### 已实现且真机验证过
| 能力 | 位置 |
|---|---|
| 五平台投递（Boss/猎聘/51job/智联/实习僧） | `com.jobpilot.{boss,liepin,job51,zhilian,shixiseng}` |
| 共享编排内核 + 全局单运行锁 | `delivery/DeliveryService`、`delivery/RunCoordinator` |
| 打分过滤（阈值/黑白名单/加减分） | `delivery/JobScorer`、`delivery/ScoreRules` |
| 投递记录 + 同岗位去重 | `deliveries` 表，唯一索引 (platform, encrypt_id, encrypt_user_id) |
| AI 打招呼话术（任意 OpenAI 兼容接口） | `ai/AiService`、`ai/GreetingService` |
| 卡密门禁（拦 `/start`）+ 一卡一机 | `license/LicenseGateFilter`、`license/LicenseService` |
| 服务端卡密管理 + 用量上报 | `license-server`，表 cards / activations / settings |

### 完全不存在（grep 0 命中，不是没找仔细）
| 缺失 |  grep 证据 |
|---|---|
| 岗位队列（先入队再投） | `queue`/`队列` 0 文件。现在是采集到就直接投 |
| 数据分析 | `analytics`/`分析` 0 文件 |
| 用户账号体系 | `account` 0 文件。服务端只认 device_id，没有 user 表 |
| 求职目标（多方向） | `求职目标` 0 文件。只有每平台的关键词列表 |
| 简历上传与解析 | drivers 里的 "resume" 只是「简历选择弹窗」处理，没有简历模块 |

### 由此得出的关键架构判断
**没有用户账号 → 用户的简历/规则/数据全在本地 SQLite。** 所以进阶版的多数能力
（多简历、数据分析、A/B 测试、AI 建议）可以**端侧实现 +  entitlement 门控**，
不需要先建一套云用户体系——这比用户设想的路子便宜一个量级。代价是没有跨设备同步。

## 3. V2 验收标准

| # | 需求 | 验收方式 |
|---|---|---|
| R1 | 服务端卡片带 `plan`（trial/standard/advanced），价格与额度走后端配置 | `wrangler d1 execute` 查 `plans` 表；发卡时可选档位 |
| R2 | 客户端能拿到 entitlement：plan + 各功能开关 + 各配额 | `/api/license/entitlement` 返回，单测覆盖降级路径 |
| R3 | 功能开关前后端都校验，不是只藏按钮 | 端侧 Service 判 + 服务端 AI 中转判额度 |
| R4 | 当日 AI 分析 / 当日投递有上限，超额即停 | 本地 daily_usage 表；单测跨天重置、超额拦截 |
| R5 | 到期不删数据，只关付费功能 | 解绑/到期后 deliveries、config 仍在 |
| R6 | 会员页展示三档、进阶60天标「最受欢迎」、无黑暗模式 | 浏览器实拍；价格取自服务端配置非硬编码 |
| R7 | 后台可赠送/延长/改套餐 | manage.html 操作 + d1 复核 |
| R8 | 全量测试通过 + 真机启动关键页面 | gradle test + 浏览器验证 |

## 4. 本期非需求（明确不做，且不在成品里假装存在）

这些用户点名要的功能**依赖尚不存在的地基**（简历模块、岗位队列），本期只做
会员与权限骨架，把它们列为下一阶段，**不在会员页里当已交付功能售卖**：

- 自然语言生成筛选规则（无简历/无结构化求职目标）
- AI 岗位匹配度 + 可解释推荐理由（需要 JD 进入投递链路，当前多数平台没带）
- 智能投递三模式（安全/智能/海投）（无队列）
- 多简历系统 + AI 选简历（无简历模块）
- 简历 A/B 测试、AI 求职建议、回复率漏斗（deliveries 表没有 已读/回复/面试/Offer 状态，平台侧也取不到）
- 「我的简历适合什么工作」传播页（无简历模块）

**替代的本期真实交付**：买断式 entitlement 骨架 + 配额强校验 + 会员页 + 后台改套餐
+ 基于 `deliveries` 表现有字段的投递统计（投递数/过滤数/失败数/按平台与方向）。
